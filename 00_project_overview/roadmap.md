# Roadmap And Current Work

This page gives readers and contributors a high-level view of where the knowledge base is going. It is a public summary, not the live task board.

The live source of truth for assignments, deadlines, review status, and to-do items should be the GitHub Project board. Each substantial piece of work should have a matching GitHub Issue.

## Current Priorities

| Area | Status | Aim |
| --- | --- | --- |
| Project overview and navigation | Active | Keep the structure clear for new readers and contributors. |
| Born-Oppenheimer and nonadiabaticity | Active | Build a complete beginner-to-advanced path through the core theory. |
| Conical intersections | Active | Clarify the physical, mathematical, and symmetry-based explanations. |
| Diabatisation deep dive | Active | Connect theory, derivations, topology, and implementation details. |
| Direct dynamics | Planned | Expand the code-facing documentation and workflow explanations. |
| MCTDH family | Planned | Develop method summaries, comparisons, and diagrams. |
| Glossary and notation | Ongoing | Keep symbols, conventions, and terminology consistent across the site. |

## Recently Expanded Areas

- The diabatisation deep dive now has a longer ADT integrability and topology sequence covering curl conditions, topological matrices, reduced Hilbert spaces, subspace construction, multistate signs, derivations, and worked examples.

## How Work Is Tracked

Use GitHub Issues for individual work items such as:

- Drafting a new page.
- Revising an existing explanation.
- Checking a derivation.
- Adding a diagram.
- Mapping an equation to code.
- Fixing broken navigation or rendering.

Use the GitHub Project board for the status of each item:

```text
Inbox
Backlog
Ready to Write
Drafting
Needs Technical Review
Needs Editorial Review
Ready to Merge
Published
Needs Update
```

For the detailed contributor workflow, see [Editorial workflow](../10_References_Guides/editorial_workflow.md).

## Update Cadence

This roadmap should be updated when:

- A new major section becomes active.
- A section changes from planned to active.
- A substantial batch of pages is published.
- The collaboration workflow changes.

Day-to-day task movement should happen on the GitHub Project board rather than on this page.
